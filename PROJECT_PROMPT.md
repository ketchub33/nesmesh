# SMESH — контекст проекта для ИИ-ассистента

Ты продолжаешь работу над 2D-файтингом **SMESH** на **Godot 4.7.2** (GDScript). Ниже всё, что уже сделано, как устроен код и как здесь принято работать. Отвечай пользователю **по-русски**: он новичок в Godot, объясняй по шагам и конкретно (куда нажать, какой файл открыть).

## Идея и ориентиры
- Платформенный файтинг в духе **Super Smash Bros / Brawlhalla**: урон копится, бойцов выбивают за границы арены, у каждого несколько жизней.
- **Механика взята из Brawlhalla** (оружия нет): 1 прыжок с земли + 2 в воздухе (у кого-то 3), уклонение вместо щита, лёгкие и заряжаемые тяжёлые атаки, восстановление, цепляние за стены.
- **Визуальный вайб:** аниме-файтинги Melty Blood: Type Lumina, Under Night In-Birth, Nitroplus Blasterz, BlazBlue — тёмная готика, чёрный/бордовый/алый, серебро и немного золота, резкие формы.
- **Экран выбора бойца** в стиле BlazBlue Cross Tag: соты-шестиугольники с портретами в центре, большие арты бойцов по бокам, скошенные плашки с именем.

## Как устроен код
- Всё рисуется вручную в `_draw()` узла Game (спрайты через `draw_texture_rect_region`, без узлов Sprite2D). Шрифт: `txt()` берёт Russo One для размера ≥ 28, иначе Oswald.
- Логика — **фиксированный шаг 60 тиков/с** (`_physics_process`), отрисовка интерполируется между тиками (`prev_pos`, `cam_prev`, `Engine.get_physics_interpolation_fraction()`).
- Состояния `state`: `title` → `menu` (выбор бойца) / `lobby` (онлайн) / `settings` → `fight` → `pause` / `over`.
- Ввод: `read_input(i)` (клавиатура + геймпад i), абстрактные действия меню `_action()`; в бою — словарь `{l r u d j atk spc sh}`. **Буфер ввода** 6 кадров для j/atk/spc/sh.
- Управление: P1 — WASD, **пробел прыжок**, F лёгкая, G тяжёлая (держать — заряд), H уклонение; P2 — стрелки, Num0/Ctrl прыжок, Num1-3 (или `, . /`); геймпад — A прыжок, X лёгкая, B тяжёлая, LB/RB/триггеры уклонение, Start пауза. W/стрелка вверх только «целятся» (прыжок на «вверх» — опция в настройках).
- Боец (`fighter.gd`): разгон/торможение через `move_toward` (инерция как в BH), короткий прыжок при отпускании, отмена восстановления удара прыжком/уклонением после попадания, отмена гравитации (лёгкая атака из воздушного уклонения), рывок двойным нажатием, цепляние за стену основной арены (`MAIN = Rect2(290,500,700,200)`), раскладки платформ `LAYOUTS` (classic/twin/steps/flat).
- Цифры бойцов — в `data/chars/<боец>.cfg` (формат ConfigFile, значения как в GDScript: `Rect2(...)`, `Vector2(...)`, массивы). Разделы `[char] [stats] [sprite] [anims]` и `[move.<имя>]`. `Fighter.load_chars()` читает их в `CHARS` (словари обновляются на месте, у каждого бойца `ch.moves`), файл с ошибкой не применяется. Список файлов — `CHAR_FILES`. В экспорт данные попадают через `include_filter="data/*"`.
- Приёмы (`ch.moves`): nlight/slight/dlight, nair/sair/dair, nsig/ssig/dsig (заряд, `CHARGE_MAX`), rec (восстановление), sheavy (рывок в воздухе), gp (удар по земле). Поля: s/a/e — разгон/активные/восстановление в кадрах, dmg, kb, sc (рост отлёта от урона), ang, box (хитбокс относительно ног).
- Урон показывается **цветом** портрета (белый→жёлтый→оранжевый→красный), без процентов.
- Персонаж со спрайтами описывается в `CHARS` полем `sprite`: `fw, fh, anchor (точка ног в кадре), scale, smooth, anims {name: [путь, кадров, fps, кадр_удара]}` + `portrait: [путь, Rect2 лица]` + `vfx: "selina"/"crimson"`. Анимации: idle run jump fall dodge attack attack2 hit (+ flash).
- Онлайн: ENet по IP, порт **24545**, хост считает игру, клиент шлёт ввод и получает снимок состояния каждый тик (`_make_snap`/`net_state`); эффекты пересылаются списком событий.
- Настройки (`user://settings.cfg`): громкость, полный экран, тряска, вибрация геймпада, прыжок кнопкой вверх; есть страница «Управление».
- ИИ: `ai_input()` в fighter.gd, 3 уровня сложности.
- **Тренировка** (кнопка в главном меню): манекен — второй боец, `dummy_input()` (стоит / прыгает / уклоняется / бьёт / CPU), бесконечные жизни, без отсчёта. Клавиши: T — режим манекена, `-` `=` — урон манекена ±10 (0 — сброс), R — сброс позиций.
- **Режим разработчика** (только оффлайн): F1 — рамки (зелёная — хёртбокс, красная — активный хитбокс, жёлтая — хитбокс на замахе, голубые — границы вылета) и над панелями — приём, кадр/всего, фаза, урон, счётчики состояний; F2 — кубики вместо спрайтов; F3 — замедление ×0.25 (`Engine.time_scale`); F4 — стоп-кадр; F5 — шаг на кадр; F6 — перечитать данные. В тренировке или с F1 файлы бойцов перечитываются сами после сохранения.

## Конвейер ассетов (пользователь не рисует — ассеты делает ChatGPT)
1. Пользователь кидает PNG-лист в `assets/`. Переложить в папку персонажа как `source.png` (латиница в именах).
2. Проверить альфу. Если «прозрачность» нарисована шахматкой — `tools/remove_checker.py` (заливка от краёв).
3. `tools/find_frames.py лист.png _tmp/boxes.png` → посмотреть рамки, вручную разделить слипшиеся кадры (кадры с полумесяцами-эффектами).
4. Скрипт нарезки по образцу `tools/cut_akane.py`: задать BOX/ANIMS/FX/PORTRAIT → полосы кадров одного размера, выровненные по корпусу (якорь = низ ног + медиана x корпуса), портрет, VFX.
5. Обновить `CHARS` (fw, fh, anchor, scale ≈ 80 / рост_тела_в_пикселях, кадр удара), проверить в движке.
- UI: `tools/cut_ui.py` режет `assets/ui/source/menu_sheet.png` и `select_sheet.png`; кнопки тянутся `draw_3slice`, окна — `StyleBoxTexture` в масштабе 0.55.
- Советы для промптов ChatGPT: «настоящий прозрачный фон PNG, без шахматки», «кадры по сетке одного размера», «без текста на элементах».

## Как проверять
- Godot: `E:\SteamLibrary\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe` (self-contained, шаблоны экспорта в `editor_data`).
- Бой CPU vs CPU: `godot --headless --path . -- --autotest [--arena=N] [--training] [--cubes]` (печатает состояние каждые 600 тиков).
- Онлайн: в фоне `-- --net-host`, затем `-- --net-join=127.0.0.1`; результаты хоста и клиента должны совпасть.
- Снимок экрана: `godot --path . --write-movie _tmp/cap/x.png --quit-after 10 -- --screen=title|menu|settings|lobby [--controls]`. Снимать **мало кадров** и сразу удалять.
- Сборка: `godot --headless --path . --export-release "Windows Desktop" build/SMESH/SMESH.exe`, затем zip папки.

- Git: локальный репозиторий, ветка `main`. GitHub-репозиторий и push пользователь делает сам.

## Правила работы с этим пользователем
- **Ничего не писать на диск C** (ни scratchpad, ни /tmp): временное — в `D:\smesh_koch_golda\_tmp`, скрипты — в `tools\`. Диск C почти полный.
- Пользователь не любит «нейрослоп» — процедурно нарисованную кодом графику. Если для фичи нужны картинки, **говорить, какие ассеты нужны**, и давать готовый промпт для ChatGPT, а не рисовать кодом.
- Не смешивать стили: одна палитра, одно «разрешение пикселя».
- Видеокарта GTX 1650 Super (4 ГБ) — локальные нейросети только для отдельных картинок (SD 1.5 через Forge), не для анимаций.
